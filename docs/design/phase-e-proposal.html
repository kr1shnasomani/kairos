Why the app reads flat even where spacing is fine

The scale has seven steps but four of them — micro 10, label 11, caption 12, body 13 — sit inside a 3px band. Four different tokens that render as one size. A hierarchy nobody can see is not a hierarchy.

It shows up concretely: an h2 on /compliance renders at 13px, the same size as the body text beneath it. On the landing the equivalent step is 64px to 44px.

One thing to settle before this ships

A signed delta implies a baseline. I have not yet confirmed the API returns one. If it does not, the arrows come out and the sparklines stay — a trend line drawn from real history is honest; a ▲ 3 computed from nothing is exactly the fabrication this product exists to refuse.

That check happens before the component is written, not after.

The plan 5 tasks · serial · shared files

Phase E cannot be parallelised the way C and D were. Those split cleanly by page because every brief owned its own files; this one is the shared files. One agent, sequential, measured at each step.

E1 The spacing scale highest risk

Replace 8 ad-hoc gap values with a 6-step scale, and give table rows a single height token. Closes review item 31, the last one still open, and it is the change that makes every other page feel like the same product.

Risk is real: this touches spacing on all 44 routes. Mitigation is the overflow guard, which already runs 7 routes × 4 widths and must stay green.

globals.css · ui.tsx

E2 The type ladder

Apply the values above. Token names do not change, so no call site moves — but every heading that was quietly rendering at body size becomes visible as a heading.

Then audit for the opposite failure: any place that hardcodes text-[Npx] instead of a token. DESIGN.md §3 calls the scale closed; drift there would undo this.

globals.css · any file with a literal size

E3 Shape and elevation

Radius 8/12px → 4/6px, moving toward the landing's sharper geometry without going fully square — a hard corner on a dense data table reads as harsh rather than precise. Hairline borders over shadows, one surface tone.

Both palettes and [data-contrast="high"] must be checked, since elevation reads differently on a dark ground.

globals.css · ui.tsx

E4 Motion

Entrance reveals on route change and on data arrival, reusing useScrollReveal and useReducedMotion — both already exist and are already used on /management.

Non-negotiable, learned the hard way on the landing: content must be readable when the observer never fires. Reveals animate transform, never opacity from zero. A page that needs JavaScript to become visible renders blank when JavaScript fails.

lib/motion.ts · app-shell.tsx

E5 KPI ticker data check first

The pattern above, on /management. Gated on confirming the API exposes a real baseline. If it does not: sparklines ship, deltas do not.

management/page.tsx · components/charts/*

Out of scope, deliberately

The landing page is not touched. It ships from main, it is deployed, and it is byte-identical in this branch. Its 768–1023px gap (74 sm:, 36 lg:, zero md:) is real and recorded, but fixing it is a separate decision — not something to fold into a token pass.
