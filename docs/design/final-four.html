The donut's accessibility was not what its test claimed

The shipped test asserted role="button" plus Enter and Space activation on each slice. It passed. In a real browser it was false: recharts overwrites every sector with tabIndex="-1", so a slice can never be tabbed to. Tabbing 120 times on /compliance never landed on one.

A button role that cannot be reached is a lie to screen readers, so it is gone. The keyboard path is the severity control the page already renders beside the chart — clicking a slice is a mouse shortcut to an action that was always keyboard-operable, not the only way in.

The test now asserts what its mock can actually prove, and says so in a comment. A mock-shaped test is exactly how the false claim survived — recharts is fully stubbed in that file, so the assertion was about a stub, never about recharts.

Why /management/coverage was the odd one out

It was the only page no phase ever assigned. Items 20 and 21 live nowhere else, so no brief ever named the file and the hand-rolled table it had from the beginning simply stayed. Every other table moved to DataTable during Phase B and got sorting and density for free.

That is a planning gap rather than an execution failure, and it is the reason a full item-by-item sweep found things a phase-by-phase reading did not.
